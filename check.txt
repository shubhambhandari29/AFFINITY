Response to DB team
-------------------

1. tblHcmAccount
   - InsertDateTime has been changed to datetimeoffset(7) NOT NULL so that every row has a compulsory insert timestamp for data-retention reporting.
   - CustomerNum will remain the primary/business key. The primary key creates an index on CustomerNum.
   - An additional index on Stage and IsSubmitted is included to support the HCM account search used by the application.

2. tblHcmAccountAssociations
   - InsertDateTime and UpdateDateTime have been added as datetimeoffset(7) NOT NULL. InsertDateTime records when the association row was created.
   - PK_Number will remain the only primary key.
   - A non-unique supporting index on ParentAccount and AssociatedAccount is included because the application retrieves associations by ParentAccount and deletes them using both account fields.

3. tblHcmOnlyUsers
   - InsertDateTime has been changed to datetimeoffset(7) NOT NULL so that every row has a compulsory insert timestamp for data-retention reporting.
   - PK_Number will remain the primary key and already has a clustered primary-key index.
   - An additional index on CustNum is included because the application retrieves HCM-only users by customer number.

The application populates InsertDateTime only when a new row is inserted. UpdateDateTime is populated on insert and whenever an existing row is updated. UTC database defaults are also included to protect inserts performed directly in SQL or by another process.
