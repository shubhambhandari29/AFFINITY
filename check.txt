


1. GENERATE LOSS RUNS FOR ALL ELIGIBLE ACCOUNTS
------------------------------------------------

Method:
POST

URL:
/loss_run/generate-all

Request body:
No request body is required.

Expected HTTP status:
202 Accepted

Example response when a new job is created:
{
  "jobId": "944430ce-f5d0-405b-b240-1b330909963b",
  "status": "queued",
  "message": "Loss-run generation has been queued"
}

If another Generate All job is already queued or processing, a second job is not
created. The API returns the existing active job:
{
  "jobId": "944430ce-f5d0-405b-b240-1b330909963b",
  "status": "processing",
  "message": "A generate-all loss-run job is already active"
}

UI action:
- Save jobId.
- Start polling the job-status endpoint.
- Do not continue waiting on the POST request after the 202 response.


2. GENERATE LOSS RUNS FOR SELECTED ACCOUNTS
-------------------------------------------

Method:
POST

URL:
/loss_run/generate

Request body:
{
  "customerNumbers": [
    "1514748014",
    "1506896261"
  ]
}

Rules:
- customerNumbers must be an array.
- At least one customer number is required.
- One selected account must still be sent inside the array.
- Duplicate and blank customer numbers are removed by the API.

Expected HTTP status:
202 Accepted

Example response:
{
  "jobId": "cbf28176-5587-4025-8e39-b9614abc4d19",
  "status": "queued",
  "message": "Loss-run generation has been queued"
}

Example invalid request response:
HTTP 422 Unprocessable Entity
{
  "detail": [
    {
      "type": "too_short",
      "loc": ["body", "customerNumbers"],
      "msg": "List should have at least 1 item",
      "input": [],
      "ctx": {"field_type": "List", "min_length": 1}
    }
  ]
}

UI action:
- Save jobId.
- Start polling the job-status endpoint.
- Disable repeated submission while the POST request is being submitted.


3. GET LOSS-RUN JOB STATUS
--------------------------

Method:
GET

URL:
/loss_run/jobs/{jobId}

Example:
/loss_run/jobs/944430ce-f5d0-405b-b240-1b330909963b

Request body:
No request body is required.

Expected HTTP status:
200 OK

Complete response structure:
{
  "jobId": "944430ce-f5d0-405b-b240-1b330909963b",
  "jobType": "all",
  "status": "processing",
  "phase": "querying_loss_run_data",
  "requestedCount": 245,
  "processedCount": 0,
  "generatedCount": 0,
  "failedCount": 0,
  "requestedBy": "user@example.com",
  "createdAt": "2026-08-25T09:30:00.000000Z",
  "startedAt": "2026-08-25T09:30:05.000000Z",
  "completedAt": null,
  "errorMessage": null,
  "failures": []
}

Field meanings:
- jobId: Unique ID returned by the generation API.
- jobType: "all" or "selected".
- status: Overall job status.
- phase: Current processing step.
- requestedCount: Total accounts in the job. It may initially be null for Generate All.
- processedCount: Accounts whose report attempt has finished.
- generatedCount: Reports successfully generated and uploaded.
- failedCount: Accounts that could not be generated.
- requestedBy: User who requested the job.
- createdAt: Time the job was submitted, in UTC.
- startedAt: Time a worker first claimed the job, in UTC.
- completedAt: Completion time in UTC; null while active.
- errorMessage: Job-level safe error message; normally null.
- failures: Account-level failures; normally returned only when failedCount is greater than 0.

Unknown job response:
HTTP 404 Not Found
{
  "detail": {
    "error": "Loss-run job not found"
  }
}

Invalid job ID format:
HTTP 422 Unprocessable Entity


4. OVERALL JOB STATUS VALUES
----------------------------

queued
- Job is stored in SQL and waiting for a worker.
- UI should show: "Waiting to start".
- Continue polling.

processing
- Worker has claimed the job and is performing one of the active phases.
- Continue polling.
- Use phase to decide which UI message and progress style to show.

completed
- Every requested account was processed successfully.
- Stop polling.
- Show generatedCount as the successful total.

partially_completed
- Processing finished, but one or more accounts failed.
- Stop polling.
- Show generatedCount, failedCount and the failures list.

failed
- The overall job could not continue, for example because the SQL query or template
  download failed, or the worker exceeded its recovery attempts.
- Stop polling.
- Show errorMessage when it is present.


5. EVERY PHASE VALUE AND EXPECTED UI BEHAVIOUR
----------------------------------------------

waiting_for_worker
Expected status: queued
Meaning: The API created the job, but a worker has not claimed it yet.
Recommended UI text: "Waiting to start"
Progress style: Indeterminate spinner.

Example:
{
  "status": "queued",
  "phase": "waiting_for_worker",
  "requestedCount": 245,
  "processedCount": 0,
  "generatedCount": 0,
  "failedCount": 0
}


starting
Expected status: processing
Meaning: A worker claimed the job and is preparing execution.
Recommended UI text: "Starting report generation"
Progress style: Indeterminate spinner.

Example:
{
  "status": "processing",
  "phase": "starting",
  "requestedCount": 245,
  "processedCount": 0,
  "generatedCount": 0,
  "failedCount": 0
}


downloading_template
Expected status: processing
Meaning: The worker is reading SACLossRunTemplate.xlsx from Databricks.
Recommended UI text: "Loading report template"
Progress style: Indeterminate spinner.

Example:
{
  "status": "processing",
  "phase": "downloading_template",
  "requestedCount": 245,
  "processedCount": 0,
  "generatedCount": 0,
  "failedCount": 0
}


querying_loss_run_data
Expected status: processing
Meaning: SQL Server is executing dbo.SAC_Loss_Run and returning the loss-run data.
This is normally the longest phase and may remain unchanged for 10-15 minutes.
The zero counts during this phase do not mean that the job is stuck.

Recommended UI text:
"Preparing loss-run data. This step may take approximately 10-15 minutes."

Progress style:
- Use an indeterminate/animated progress indicator.
- Do not show 0% progress.
- The UI may display "245 accounts identified" when requestedCount is available.

Example:
{
  "status": "processing",
  "phase": "querying_loss_run_data",
  "requestedCount": 245,
  "processedCount": 0,
  "generatedCount": 0,
  "failedCount": 0
}


generating_reports
Expected status: processing
Meaning: The SQL query is complete. The worker is creating Excel files and uploading
them to Databricks.
Recommended UI text: "Generating and saving Excel reports"
Progress style: Determinate progress bar.

Progress calculation:
processedCount / requestedCount * 100

Example:
{
  "status": "processing",
  "phase": "generating_reports",
  "requestedCount": 245,
  "processedCount": 84,
  "generatedCount": 82,
  "failedCount": 2
}

Recommended UI detail:
"84 of 245 accounts processed - 82 generated, 2 failed"


finished
Expected status: completed or partially_completed
Meaning: All account-level processing has finished.
Progress style: 100% complete.
Stop polling.

Successful example:
{
  "status": "completed",
  "phase": "finished",
  "requestedCount": 245,
  "processedCount": 245,
  "generatedCount": 245,
  "failedCount": 0,
  "completedAt": "2026-08-25T09:45:20.000000Z",
  "errorMessage": null,
  "failures": []
}

Partial-completion example:
{
  "status": "partially_completed",
  "phase": "finished",
  "requestedCount": 245,
  "processedCount": 245,
  "generatedCount": 243,
  "failedCount": 2,
  "completedAt": "2026-08-25T09:45:20.000000Z",
  "errorMessage": null,
  "failures": [
    {
      "customerNumber": "1514748014",
      "reason": "No loss-run records found"
    },
    {
      "customerNumber": "1506896261",
      "reason": "Failed to generate or upload workbook"
    }
  ]
}


failed
Expected status: failed
Meaning: The complete job stopped because of a job-level error or exceeded its
recovery attempts.
Recommended UI text: "Loss-run generation failed"
Progress style: Error state.
Stop polling.

Example:
{
  "status": "failed",
  "phase": "failed",
  "requestedCount": 245,
  "processedCount": 0,
  "generatedCount": 0,
  "failedCount": 0,
  "completedAt": "2026-08-25T09:40:00.000000Z",
  "errorMessage": "Loss-run generation failed. Check application logs for details.",
  "failures": []
}

Important distinction:
- failedCount represents account-level failures.
- errorMessage represents a failure of the overall job.
- A job-level failure can therefore have failedCount = 0.


6. UI POLLING RULES
-------------------

Recommended polling interval:
10-15 seconds.

Continue polling while status is:
- queued
- processing

Stop polling while status is:
- completed
- partially_completed
- failed

Do not stop polling merely because counts have not changed during
querying_loss_run_data. That phase is expected to remain unchanged for several
minutes.

Suggested UI flow:
1. User clicks Generate.
2. Disable the button while the POST request is being submitted.
3. Receive HTTP 202 and save jobId.
4. Show a non-blocking status panel or notification.
5. Poll GET /loss_run/jobs/{jobId} every 10-15 seconds.
6. Change the UI message based on phase.
7. Allow the user to continue using the application or leave the page.
8. Stop polling when a terminal status is returned.
9. Display account failures only when failedCount is greater than 0.


7. AUTHENTICATION AND COMMON HTTP RESPONSES
-------------------------------------------

401 Unauthorized
The login/session cookie is missing or expired.

Example:
{
  "detail": {
    "error": "Not authenticated"
  }
}

202 Accepted
The generation request has been accepted and is running asynchronously.
It does not mean that Excel generation has completed.

200 OK
The status request succeeded.

404 Not Found
No job exists for the supplied jobId.

422 Unprocessable Entity
The request payload or jobId format is invalid.

500 Internal Server Error
The API could not create or retrieve the job because of an unexpected backend
error. The UI should show a general error and allow the user to retry.
